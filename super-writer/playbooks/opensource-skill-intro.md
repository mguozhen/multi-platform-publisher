# 开源项目 / skill 介绍 Playbook

> 类型: 介绍一个开源项目或 skill 的图文
> 蒸馏来源: 公众号「金色传说大聪明」介绍花叔「女娲.skill」一文
> 适用: Hunter 介绍别人的开源项目，或自己发布的 skill
> ⚠️ 这个类型**不走卡兹克风**——用下面这套排版/样式，可以用冒号、Q 前缀、箭头

## 核心定位

第三方介绍者视角。「我替你看了这个项目（或这期视频），整理成一篇能让你 30 秒看懂、5 分钟上手的图文」。
不吹捧，用具体数字和真实 demo 说话。给项目作者足额 credit。

## 排版 / 样式（要复刻的硬规范）

- 顶部一个全大写英文 eyebrow 标签，例 `OPEN SOURCE`
- GitHub 链接**裸贴**，单独成行，不加 markdown 链接语法
- 图多。每张图下面配一句**图片说明文字**（描述这张图是什么）
- 列表用 `→` 箭头打头，不用 markdown 的 `-`
- 并列的同级概念用 `·` 中点连接（例「心智模型 · 决策启发式 · 表达 DNA」）
- 步骤/阶段用中文序号「第一阶段 / 第二阶段」
- 抛问题用 `Q` 前缀单独成行（例 `Q 普通人怎么在 AI 时代赚钱`）
- 引用项目作者原话时点明出处（例「作者的原话：……」）
- 段落短，口语，有网感（梗、自嘲、调侃都可以）

## 内容结构（12 段式，按顺序）

```
1  开场钩子   谁做的 + 一个炸裂数字（一周 8k star）+「又整了个新活」
2  GitHub 裸链接
3  这是什么   一句通俗话 ——「你给它 X，它就 Y」
4  名字的梗   项目名字的由来 / 梗
5  已有成果   具体列举（已蒸馏 17 个人物，把名字列出来）
6  来源声明   拿到授权，整理自 XX 的视频 / 原帖
7  先看效果 ★ 挑一个最炸的具体 demo：输入 → 输出，最好带对比
8  怎么做的   拆解机制 / 原理，分阶段讲清楚
9  更多玩法   第二、第三个用例
10 怎么用     安装命令裸贴 + 自然语言用法示例
11 关于作者   项目作者 bio（代表作、背景、出圈数据）
12 收尾       GitHub 地址 + 原始来源（视频 / 原帖）链接
```

第 7 段是全文重心。demo 必须具体到让人「卧槽」，不能只讲概念。

## 标题公式

`[一句话亮点]，[谁]开源的「[项目名]」，[炸裂数字]`
例：蒸馏万物成 skill，B站UP花叔开源的「女娲.skill」，一周 8k star

## 声音

- demo 优先于描述。先给一个具体例子，再讲原理
- 通俗第一。任何术语都翻成大白话「你给它 X 它就 Y」
- 用对比凸显价值（蒸馏版 vs ChatGPT 角色扮演那种平庸版）
- 给项目作者足额 credit：引原话、写 bio、放链接
- 不抽象吹捧，用具体数字（8k star / 17 个人物 / 40 多个来源 / 半小时）
- 网感口语，梗和自嘲随意用
- 收尾留一句有点意思的话（例「你想蒸馏的下一个员工，何必是同事」）

## 这个类型专属铁律

- 必须有一个真实可跑的 demo，不能通篇概念
- 安装命令 + 用法给全，读者看完能当场上手
- 项目作者 credit 给足（原话 / bio / 链接），介绍别人的项目尤其重要
- 收尾必给 GitHub 链接 + 原始来源
- 介绍 Hunter 自己的 skill 时，第 11 段「关于作者」换成「为什么我做这个」

## 两种子型 — 写之前先选

这个 playbook 有两种子型，按读者和目的选：

- **介绍型**（上面的 12 段式）——目的是「让人 30 秒看懂这是什么、想试」。读者已有一定基础。
- **手把手教程型**（下面这套）——目的是「让小白照着做、当场跑通」。读者可能完全不懂技术。

同一个 skill 可以两种各写一篇：先发介绍型种草，再发教程型转化。

## 手把手教程型（STEP-by-STEP 图文并茂）

> 蒸馏来源: Buluu 公众号《终于完成了！实测效率提升10倍，电商评论深度分析Skill已就位！》
> 适用: 给完全不懂技术的小白讲清楚「这个 skill 怎么用」，照着 4 步当场跑通

### 核心原则

- **不是说明书，是带你跑一遍**。说明书罗列功能；教程型走一条完整路径，每步「你现在该做什么」。
- **小白能跟上**。任何术语先翻成大白话。默认读者不懂代码、没装过环境。
- **每个 STEP 配一张图**。图不是截图堆叠，是一张说清这步在干嘛的设计图（流程图 / 标注图）。
- **降低第一次的门槛**。每步给「第一次建议先 X」的保守提示（先抓 50 条跑通，别一上来 1000 条）。

### 结构（导语 + 原理 + 4 STEP + 安装 + 收尾）

```
导语框（>）   【手把手教程】一句话承诺：哪怕不懂技术，4 步 N 分钟跑通
开场         口语个人开场（Hello 我是 Hunter）+ 一个读者都干过的痛苦场景
一句话原理   加粗一段，把 skill 做的事讲透「你给它 X，它自动 Y，给你 Z」
[图：原理]   一张三节点流程图（输入 → AI 自动跑 → 产出）
它帮你省了什么  跑之前先说清价值。把活拆成「它擅长 / 你不擅长」的几个环节
STEP 1 准备   读者要准备的唯一一样东西（一个 ASIN）。给「第一次建议」
[图：STEP 1]
STEP 2 调用   一句大白话指令就行。给保守提示（先抓 50 条）
STEP 3 自动跑  「你去倒杯咖啡」——强调它自己干。可顺带讲一句技术亮点
[图：STEP 3]
STEP 4 验收   跑完拿到什么。★ 这里放一个真实洞察举例（带引用块的具体结论）
[图：STEP 4]
一键安装      安装命令裸贴 + GitHub 裸链接
收尾          拉回到一个更大的判断（差评是竞品免费送你的需求清单）
```

### 配图规范（教程型专属）

教程型的图不是截图，是**设计图**。每张图一个 HTML 渲染成 PNG：

- 统一视觉：浅色底（小白友好，别用暗黑科技风）、品牌主色一个、圆角卡片
- STEP 图左上角放一个胶囊标签「STEP N · 动作」
- 大标题用一句口语短句（「你去倒杯咖啡，剩下它自己干」），不用功能名
- 流程用「卡片 → 箭头 → 卡片」，底部一句话点睛（带高亮数字）
- HTML 源 + PNG 存 `content/_covers/<skill>-tut/`，正文 `[图：说明]` 标记 → image_map

参考实现：`content/_covers/voc-tut/`（cover/principle/step1/step3/step4 五张）。

### 标题公式（教程型）

`[读者的痛苦] + [一句话承诺]`
例：亚马逊卖家别再熬夜读差评了——输入一个 ASIN，5 分钟出一份竞品洞察报告

### 教程型铁律

- STEP 4 必须有一个真实洞察举例，用引用块（`>`）放一句具体结论，不能只讲「会生成报告」
- 每个有门槛的 STEP 给「第一次建议」的保守提示
- 全程「你」视角，是在带读者做，不是在介绍产品
- 收尾不收在功能，收在一个让人记住的判断句

## 实战定稿要点（多轮迭代后锁定）

**分段**——每段 2-4 句合成一行，不要每句一段。每句一段会让段间距爆炸。
源文件里一行 = 一段，句子在段内用句号自然流动。

**排版**——`wechat_draft.py` 渲染器已严格复刻样本公众号（金色传说大聪明）：
正文 15px / 行高 1.9 / 段只留 14px 下边距；小标题衬线字体 + 上方分隔线；
OPEN SOURCE 等宽橙红 eyebrow。写作只管内容，不碰 HTML。

**划线**——关键判断句用 `**加粗**`（渲染成样本同款 strong 强调）。

**配图**——用**真实素材**，绝不 AI 发散生成：GitHub 仓库主页截图、terminal
实跑截图。正文放 `[图：说明文字]` 标记，调用方传 `image_map` {说明: 真实图路径}。
没有真实图的标记直接删掉，宁缺毋滥。

**定位**——介绍自己的项目时，不写「跨境 SaaS 七年」「出海老兵」这类。
对外是硅谷最前沿的 AI 公司（见 persona.md 语气陷阱）。
