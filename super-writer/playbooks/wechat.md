# 微信公众号 Playbook

> 平台: 微信公众号「Hunter 在跑」
> 风格: 卡兹克风 (khazix-writer skill)
> 频率: 每周三深稿 / 每周日复盘

## 核心定位

「有见识的董事长在认真聊一件打动他的事」。
不是评测博主，是真在做事的人。题材来自真实 build / 决策 / 行业观察。

## 三种 playbook 变体（发之前选一个）

### variant A — 行业观察长文（推荐，最强信用）
观察一个现象 → 层层深入 → 文化升维。
```
例: 「Anthropic 一刀下来，LLM 中转站这门生意要死一半」
结构: 开头具体事件 → 背景科普 → 3-4 板块展开 → 文化升维 → 收尾
字数: 4500-6000
```

### variant B — 调查实验复盘
亲自下场做一件事，报道发现。
```
例: 「Codex vs Claude Code，我同时用了 1000 小时」
结构: 遇到的好奇/困境 → 一步步做 → 5 个真实场景 → 总结分类法
字数: 5000-7000
```

### variant C — 个人决策自白
公开一个集团/产品的真实决策 + 为什么。
```
例: 「我决定公开 Shulex FY2025 财报」
字数: 3000-4500
风险: 涉及财务/真实人物需先脱敏确认
```

### variant D — 转述解读型（拆解一篇值得读的外部观点）
拿一篇值得让更多人读懂的外部文章 / X thread，带读者读懂，叠加自己的判断与疑问。
核心承诺：「我替你读懂了这篇，还加了我自己的判断」。
对标：深思圈《怎么看 Anthropic 进军金融》（转述 Reid Hoffman）。
```
例: 「Reid Hoffman 这篇 Anthropic 进军金融，我读了三遍」
结构:
  开头   介绍源 + 作者是谁为什么可信 + 个人钩子（"有两三句话戳到我"）
  编号节  01-09，每节配一张图（占位）
  每节    先转述源的一个点 → 再叠加「我」的反应 / 疑问 / 类比
  倒数二节「对我们意味着什么」— 落到读者，给行动视角
  收尾   诚实点出源绕过去的盲点 + 来源链接
字数: 5000-6500
```
这个类型专属铁律:
- 给原作者公正 — 不能只截对你论点有利的片段，要呈现完整论证弧
- 每个转述点都要有「我」的增量（一个疑问 / 类比 / 不安），否则是翻译不是解读
- 源里的金句做 pull-quote 并署名；关键比喻单独成段；多维数据做对比表格
- 暴露真实的「读懂过程」（"我读了三遍，第三遍才懂"），不假装一眼通透
- 结尾留一个连原作者都没回答的开放问题，把思考交还读者

### variant E — 开源项目 / skill 介绍型
介绍一个开源项目或 skill。两种子型，完整规范见 `playbooks/opensource-skill-intro.md`：
⚠️ 这个变体**不走卡兹克风**。
```
E1 介绍型   让读者 30 秒看懂、5 分钟上手。12 段式。读者已有基础。
            例:「蒸馏万物成 skill，花叔开源的「女娲.skill」，一周 8k star」
E2 教程型   手把手 STEP-by-STEP 图文并茂，带小白照着跑通。
            导语框 → 一句话原理 → 4 个 STEP（各配设计图）→ 安装 → 收尾
            例:「亚马逊卖家别再熬夜读差评了——输入一个 ASIN，5 分钟出报告」
字数: 2500-4000
```
重心：E1 第一个 demo 要「卧槽」；E2 每步配设计图 + STEP 4 放真实洞察举例。
同一 skill 可两篇都写：E1 种草 → E2 转化。

### variant F — 新特奇型（热点事件冲击播报）
抓一个 24-72h 内的炸裂热点事件，冲击式播报。⚠️ 完整规范见 `playbooks/xinteqi.md`。
对标：新智元 / 量子位 的 AI 爆款热点稿。
```
例: 「3个人带100个AI程序员，月烧130万美元！OpenAI：钱我出」
结构: 冲击开场(3句见数字) → 数字拆解+加码 → 机制解释 → 升维(降价推演/视角) → 金句收尾
字数: 1500-2800（快稿，不是深度长文）
```
铁律：必须有一个炸裂数字；纯新闻播报，全程第三人称，不写「我」。

### variant G — 工具实测对比型（我用 X 做了同一件事，复盘谁更好）
亲自用多个工具 / 方案做同一件事，给出有证据的结论。比纯评测可信，因为「我真的全做了一遍」。
```
例: 「我卸载了 OpenClaw 和 Hermes — 搭自媒体生产线只有 Claude Code 能打」
结构: 先抛结论 → 设定同一个任务 → 逐维度对比(每维度配具体证据) → 升维(差距的本质) → 决策收尾
字数: 2200-3500
```
铁律：
- 每个对比维度必须有**具体证据**（耗时 / 做出来的东西 / 真实发生的例子），不能只有形容词
- 对落败方对事不对人，靠证据不靠情绪——情绪化的贬低反而削弱说服力
- 结论前置（开头就给），正文是「为什么」的论证，不是悬念
- 收尾落到一个更大的判断（这不是工具差距，是某种能力的差距）

## 公众号深度文规范（Hunter 实战经验，所有变体通用）

**语言**
- 短句优先，多换行留白。真诚、专业、带一点极客的分享欲。拒绝任何 AI 腔词汇。
- 开篇必须有反常识钩子或数字冲击（例「一篇文章带来 6000 元，不是因为文章好，是因为结构对」）。

**字数**：深度解析 3000-5000+ 字，不要写成短平快。

**两种可选风格**（按选题挑）
- 智东西产业观察风：客观编译 + 轻度行业点评，开篇有导语 / 编译者视角，用词专业克制。
- 一泽 Eze 极客白话风（技术解析专用）：口语化长短句交错，场景代入的「刻板印象」描述，层层递进的「填坑血泪史」视角。写成「踩坑神级代码分享」，不是说明书。

**排版四件套（2026-05 实战验证，缺一就是一坨白字）**
- 顶部导语框：正文第一行用 `> 【…】一句话…` 引用语法 → 渲染成灰底红边 callout（同新智元「导读」）
- 关键数字 / 关键短语全部 `**加粗**`，让读者一眼抓到信息钩子
- 每个板块一个 `#` 小标题（衬线 + 分隔线，渲染器自动）
- 每 2-4 段插一张图，绝不让纯文字连续超过半屏

**配图规范（设计图优先，不用 AI 糊图）**
- 每篇 3-4 张。优先**设计图**：HTML/CSS → Chrome 截图，模版见 `content/_covers/inline-*.html`
- 统一深色科技风：`#08080b` 底 + 网格纹理 + 红光晕，和封面同一视觉体系
- 配图类型：数据卡（大数字 infographic）/ 流程示意图 / 推演时间线 / 真实截图
- 正文放 `[图：图注]` 标记，发布时 `image_map` 把图注映射到本地 PNG（`add_draft(..., image_map={...})`）
- ❌ 不用 AI 乱生成的糊图；❌ 配图不出现人脸
- 排版（圆角、居中、图注、禁 ul/li）由渲染器强制，写作只管放标记

**发布前必做：本地预览截图**
- `wechat_draft.preview(title, body, image_map)` → 渲染成本地 HTML，Chrome 截图，先看排版再推草稿
- 持续迭代排版就靠这个预览环，不用每次开公众号后台

**深度铁律**：拿到长视频 / 文章链接，先拉全量字幕 / 全文深度分析长尾观点，杜绝不看全片就开写。

## 写作铁律（khazix-writer）

- 开头从具体事件切入，绝不宏大叙事
- 不用小标题，口语转场句衔接（"回到 X 这块"）
- 不用冒号 / 破折号 / 双引号（用「」）
- 禁用词: 说白了 / 本质上 / 换句话说 / 综上所述 / 值得注意
- 每篇至少 1 处文化升维
- 一句话独立成段制造重量

```
触发 khazix-writer skill：

```
